Overall Objective

Segment e-commerce customers by purchase behavior using RFM analysis, then train a classifier to auto-label new customers — visualizing everything with PCA-reduced cluster plots.

Development Phases
PHASE 00

Environment Setup & Data Acquisition

  • Install Python & create a virtual environment

    Use Python 3.10+ and set up an isolated environment via venv or conda. This prevents dependency conflicts across projects.

    Python 3.10+ venv / conda pip

    Why: Reproducibility. Any collaborator (or your future self) can recreate the exact environment.

  • Choose your development environment: Jupyter Notebook

    Use JupyterLab or classic Jupyter Notebook. It lets you interleave code, plots, and markdown explanations — ideal for exploratory data work. Run pip install jupyterlab.

    JupyterLab VS Code + Jupyter ext.

    Why: Notebooks are the industry standard for iterative data exploration and communicating findings.

  • Install core libraries

    Install everything you'll need upfront. Run: pip install pandas numpy scikit-learn matplotlib seaborn plotly scipy.

    pandas numpy scikit-learn matplotlib seaborn plotly scipy

    Why: These are the foundational open-source data science libraries; all free, all battle-tested.

  • Download the UCI Online Retail Dataset

    Go to Kaggle.com and search for "UCI Online Retail". The dataset is free and contains ~500k transactions with fields like CustomerID, InvoiceDate, Quantity, and UnitPrice.

    Kaggle (free account) UCI ML Repository

    Why: This dataset is well-known, clean enough to learn on, and perfectly structured for RFM analysis.

PHASE 01

Exploratory Data Analysis (EDA)

  • Load the data and inspect its structure

    Use pd.read_excel() or pd.read_csv() to load the file. Call .info(), .head(), and .describe() to understand column types, ranges, and missing values.

    Why: You can't clean what you don't understand. This step anchors all downstream decisions.

  • Identify and handle data quality issues

    Look for: missing CustomerIDs (rows to drop), negative quantities (returns/cancellations), duplicates, and zero unit prices. Log and document every decision you make.

    Why: Dirty data produces meaningless clusters. Your RFM scores must reflect real purchase behavior.

  • Visualize distributions of key variables

    Plot histograms of Quantity, UnitPrice, and transaction counts per customer. Use seaborn's histplot and boxplot. Note heavy skews — these will affect your feature engineering.

    Why: Visual patterns reveal outliers and skewness you must account for before clustering.

📌 Learning checkpoint After EDA, you should be able to describe: what fraction of transactions have missing CustomerIDs, the typical order value range, and whether there are seasonal purchase spikes. Write these findings as markdown cells in your notebook.
PHASE 02

RFM Feature Engineering

  • Define the RFM snapshot date

    Choose a reference date — typically one day after the dataset's last transaction date. All recency calculations are relative to this date.

    Why: RFM is temporal; the snapshot date determines how "recent" each customer actually is.

  • Compute Recency (R)

    For each CustomerID, find the date of their most recent purchase. Calculate the number of days between that date and the snapshot date. Lower = more recent.

    Why: Recency is often the strongest predictor of future purchases — recently active customers are warmer leads.

  • Compute Frequency (F)

    Count the number of distinct invoices per customer (not the number of line items). Use groupby('CustomerID')['InvoiceNo'].nunique().

    Why: Frequency captures loyalty — how often does a customer return to buy?

  • Compute Monetary Value (M)

    Create a TotalSpend column (Quantity × UnitPrice), then sum it per customer. This is total lifetime spend.

    Why: Monetary value identifies your highest-value customers — the ones who drive revenue.

  • Scale the RFM features

    Apply StandardScaler or RobustScaler from scikit-learn. Consider log-transforming heavily skewed columns first. Store the scaler object — you'll need it later for the classifier.

    sklearn.preprocessing.StandardScaler sklearn.preprocessing.RobustScaler numpy.log1p

    Why: K-Means is distance-based; unscaled features with large ranges dominate cluster assignment unfairly.

PHASE 03

Unsupervised Clustering — K-Means & Hierarchical

  • Determine the optimal number of clusters (K)

    Run the Elbow Method: plot inertia (within-cluster sum of squares) for K = 2 to 10. Also compute the Silhouette Score for each K. Look for the "elbow" inflection point and the highest silhouette value.

    sklearn.cluster.KMeans sklearn.metrics.silhouette_score

    Why: Choosing K arbitrarily produces meaningless clusters. This step gives you data-driven justification.

  • Fit K-Means with the chosen K

    Train KMeans(n_clusters=K, random_state=42) on your scaled RFM dataframe. Assign cluster labels back to your customer dataframe as a new column.

    Why: K-Means is fast, interpretable, and the go-to algorithm for customer segmentation tasks.

  • Explore with Hierarchical Clustering (Dendrogram)

    Use scipy.cluster.hierarchy.linkage and dendrogram on a sample (≤500 customers) to visualize the merging hierarchy. Compare the cut-point with your K-Means K choice.

    scipy.cluster.hierarchy sklearn.cluster.AgglomerativeClustering

    Why: Hierarchical clustering reveals nested structure and validates whether your chosen K is natural in the data.

  • Profile and label each cluster

    Group by cluster label and compute the mean R, F, and M for each group. Give human-readable names to each segment — e.g., "Champions", "At-Risk", "Hibernating", "New Customers".

    Why: Business stakeholders need interpretable segments, not just cluster ID numbers.

PHASE 04

Dimensionality Reduction & Visualization

  • Apply PCA to reduce to 2 components

    Use sklearn.decomposition.PCA(n_components=2) on your scaled RFM features. Transform the data and store the 2D coordinates alongside cluster labels.

    sklearn.decomposition.PCA

    Why: You can't directly plot 3D RFM space. PCA projects the data onto 2 axes that capture maximum variance, making clusters visually interpretable.

  • Plot the 2D cluster scatter chart

    Use seaborn.scatterplot with hue=cluster_label, or use plotly.express.scatter for an interactive version. Color-code each segment and add a legend with segment names.

    seaborn plotly.express matplotlib

    Why: A clear cluster plot is your primary visual proof that the segmentation worked. It's the centerpiece of your dashboard.

  • Add supporting visualizations

    Create bar charts of average R, F, M per cluster; a heatmap of cluster centroids (seaborn's heatmap); and a pie chart showing the % of customers per segment.

    Why: Multi-angle visuals tell the complete story — size, behavior profile, and separation of each segment.

📌 Conceptual bridge moment At this point you have discovered segments from raw data with no labels — pure unsupervised learning. The next phase asks: "Can a machine learn to assign future customers to these same segments automatically?" That's the transition from unsupervised to supervised learning.
PHASE 05

Supervised Classifier — Automating Segment Assignment

  • Prepare the supervised learning dataset

    Your input features are the scaled RFM values. Your target labels are the K-Means cluster IDs you assigned in Phase 3. Split into train/test sets using train_test_split(..., test_size=0.2, random_state=42).

    sklearn.model_selection.train_test_split

    Why: The cluster labels from unsupervised learning now serve as "ground truth" for supervised training — the key conceptual bridge.

  • Train a K-Nearest Neighbors (KNN) classifier

    Use sklearn.neighbors.KNeighborsClassifier. Start with K=5. Fit on training data. This is your first model — keep it simple.

    sklearn.neighbors.KNeighborsClassifier

    Why: KNN is intuitive ("assign to the nearest group") and reinforces the distance-based logic you used in K-Means clustering.

  • Also train a Logistic Regression classifier

    Use sklearn.linear_model.LogisticRegression(multi_class='ovr', max_iter=500). Compare its predictions against KNN.

    sklearn.linear_model.LogisticRegression

    Why: Comparing two models is good scientific practice; it also introduces you to the idea of model selection.

  • Evaluate both classifiers

    Compute accuracy_score, a classification_report (precision, recall, F1 per segment), and plot a confusion matrix as a heatmap. Note which segments are hardest to classify correctly.

    sklearn.metrics.accuracy_score sklearn.metrics.classification_report sklearn.metrics.ConfusionMatrixDisplay

    Why: A model without evaluation is a black box. You need to know where it fails before trusting it in production.

  • Demonstrate prediction on a new (fictional) customer

    Create a dict with made-up R, F, M values. Scale it using the same scaler from Phase 2. Pass it through your best classifier. Print the predicted segment name.

    Why: This is the "wow" moment — your pipeline can now automatically label any new customer in real time.

PHASE 06

Final Assembly & Reflection

  • Clean up and structure your notebook

    Add clear markdown headers, section descriptions, and interpretation cells between each code block. Make your notebook readable as a standalone document — someone should understand what you did without running the code.

    Why: Communication is half the job. A well-documented notebook is also your portfolio artifact.

  • Write a conclusions section

    Summarize: how many segments you found, what characterizes each one, which classifier performed better and why, and one business recommendation based on the segmentation.

    Why: Translating analytical findings into business language is the skill that makes data science valuable.

  • Reflect on what each technique contributed

    Write 3–5 sentences answering: "What did K-Means give you that Logistic Regression couldn't, and vice versa?" This reflection cements the unsupervised→supervised conceptual bridge.

    Why: Metacognitive reflection is what turns completed projects into deep, lasting knowledge.
